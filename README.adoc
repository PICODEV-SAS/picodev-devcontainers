= picodev-devcontainers
:toc: macro

Environnements de développement de Picodev CTF : une image par famille de
microcontrôleurs, à ouvrir depuis VS Code en *Dev Containers* ou en *Remote-SSH*, et
un projet de départ par famille (`starters/`, aussi publié seul :
`PICODEV-SAS/picodev-starter-<famille>`).

toc::[]

== Images

`ghcr.io/picodev-sas/dev-<famille>:2026.2`, paquets publics (aucune connexion à GHCR),
amd64 et arm64, signés avec cosign. Chaque image part de l'image de compilation de sa
famille (`toolchains/`, tiré de picodev-lab-workers au commit épinglé dans le `Makefile`) : ce qui compile dans le conteneur compile au service de
compilation Picodev, avec les mêmes versions.

Versions exactes de tout ce qu'une image contient : `/opt/picodev/versions.json`.
Rien de secret dans les images : ni défi, ni solution, ni jeton, ni clé (les clés
d'hôte SSH sont créées au démarrage de chaque conteneur).

== Se servir d'une image

* *Dev Containers* : ouvrir un projet de départ, « Reopen in Container ».
* *Remote-SSH* :
+
----
docker run -d --name picodev-avr -p 127.0.0.1:2222:22 \
  -e SSH_AUTHORIZED_KEYS="$(cat ~/.ssh/id_ed25519.pub)" ghcr.io/picodev-sas/dev-avr:2026.2
ssh -p 2222 picodev@127.0.0.1
----
+
puis, dans VS Code, « Remote-SSH: Connect to Host… » vers `picodev@127.0.0.1:2222`.

== Licences

Notre code (Dockerfiles, scripts, tests) : Apache-2.0 (`LICENSE`, `NOTICE`). Projets de
départ : MIT. Binaires GPL des fabricants et leurs sources : `SOURCES.md` ; offre
écrite pour la source de tous les binaires GPL et LGPL des images, Debian compris :
`base/SOURCES-OFFER`, aussi dans chaque image (`/opt/picodev/SOURCES-OFFER`).

Vérifier la signature d'une image :

----
cosign verify ghcr.io/picodev-sas/dev-avr:2026.2 \
  --certificate-identity-regexp '^https://github.com/PICODEV-SAS/picodev-devcontainers/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
----

== Construire et tester

----
make test-avr        # ou base, esp32, stm32, nrf52 : image amd64, puis tests/test-image.sh
make vscode-avr      # extensions installées par le serveur VS Code, en SSH
make clean-avr
----

`make` construit d'abord les images de compilation depuis `toolchains/`. Rien n'est
poussé. Publication : `.github/workflows/publish.yml`, à la main seulement, sur ce
dépôt ; `dry_run` construit les deux architectures sans rien pousser.
